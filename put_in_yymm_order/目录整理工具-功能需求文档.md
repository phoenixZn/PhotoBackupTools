# 目录整理工具-功能需求文档

## 1. 文档目标

本文档用于定义“目录整理工具”的完整功能需求。  
目标是：将文档交付给任意开发者后，对方无需参考原始代码，也能重新设计并实现**功能等价**的程序（CLI + GUI）。

---

## 2. 适用范围与运行环境

- 实现语言：Python 3
- 平台范围：Windows / macOS
- 路径处理：必须使用 `pathlib` 或 `os.path`，确保跨平台路径兼容
- GUI 框架：`tkinter`
- 可选依赖：`tkinterdnd2`（仅用于目录拖拽增强）

---

## 3. 交付物要求

至少包含以下文件（命名可调整，但职责必须等价）：

1. **CLI 核心脚本**（示例：`organize_by_month.py`）
  - 负责文件扫描、移动、冲突处理、统计、日志落盘、结构化事件输出
2. **GUI 启动器脚本**（示例：`gui_launcher.py`）
  - 负责参数收集、执行确认、调用 CLI、展示日志与进度
3. **一键启动脚本**（示例：`start_gui.bat`，Windows）
  - 双击启动 GUI
4. **依赖清单**（示例：`requirements.txt`）
  - 至少包含可选拖拽依赖声明（`tkinterdnd2`）

---

## 4. 核心业务目标

给定一个“根目录”，将其中**所有文件（含子目录）**按“修改时间的年月”归档到根目录同级的新目录中：

- 目标备份目录命名：`{根目录名}_YM`
- 月份子目录命名：`YYYY_MM`（如 `2026_04`）

整理过程中必须保证：

- 不覆盖已有文件
- 出错不中断整体流程（单文件失败不影响后续）
- 可输出详细过程日志、汇总统计、按月统计

---

## 5. CLI 功能需求

### 5.1 命令行参数

CLI 至少支持以下参数：

- `--root <path>`：必填，待整理根目录
- `--remove-empty-dirs`：可选，整理完成后尝试删除原根目录下变为空的子目录
- `--yes`：可选，跳过交互确认
- `--json-events`：可选，输出结构化事件行（供 GUI 实时解析）
- `--ext-whitelist <text>`：可选，文件类型白名单；为空时整理全部文件，非空时仅整理命中后缀文件（支持空格/逗号/分号分隔，如 `.jpg .png,.mp4`）

示例：

- `python organize_by_month.py --root "D:/demo/source_dir" --yes --ext-whitelist ".jpg .png .mp4"`
- `python organize_by_month.py --root "D:/demo/source_dir" --yes --ext-whitelist "jpg,PNG;.mov"`

### 5.2 执行前安全确认

未指定 `--yes` 时，必须提示并等待用户确认：

`此操作将移动所有文件到月份文件夹，是否继续？`

用户拒绝后应立即退出，退出码为成功退出（非异常）。

### 5.3 输入合法性校验

执行前必须校验：

- 根目录存在
- 根路径是目录

不满足时输出错误并返回非零退出码。

### 5.4 文件扫描与归档规则

- 递归扫描根目录下所有文件（包含任意深度子目录）
- 若白名单非空，仅处理后缀命中白名单的文件（大小写不敏感，`jpg` 与 `.JPG` 视为同类型）
- 白名单解析需支持空格、英文逗号、分号分隔；可自动补全前导点（如 `jpg` 视为 `.jpg`）
- 每个文件按 `mtime`（修改时间）计算目标月份目录 `YYYY_MM`
- 创建目标目录：
  - `{root_parent}/{root_name}_YM/{YYYY_MM}`
- 将文件移动到对应月份目录

### 5.5 同名与“同文件”处理规则（关键）

当目标月份目录出现同名文件时，必须按以下顺序处理：

1. 先判断是否“同文件”
  - 高性能规则：`文件名相同` 且 `文件大小相同`，即视为同文件
2. 若判定同文件：
  - **不移动**
  - 记录 `Skip` 日志
  - 计入“跳过数”
3. 若同名但大小不同：
  - 自动重命名目标文件名（`name_1.ext`, `name_2.ext`, ...）
  - 不可覆盖已存在文件
  - 记录重命名告警日志
  - 计入“重命名数”

### 5.6 移动安全性（防丢失）

移动必须满足“尽量无损”策略：

- 同盘优先使用原子替换/重命名能力（如 `Path.replace`）
- 若出现跨设备等场景，回退为：
  - 先复制（保留元数据）
  - 再做基本校验（至少校验大小）
  - 校验通过后再删除源文件
- 任何校验失败都不可删除源文件
- 任何移动失败记录为失败项并继续处理下一个文件

### 5.7 空目录清理

当启用 `--remove-empty-dirs`：

- 仅处理“原根目录下的子目录”
- 仅删除空目录
- 删除顺序应从深到浅（先叶子后父级）
- 非空目录、权限不足等异常不应导致整体失败

---

## 6. 日志输出需求

### 6.1 实时过程日志格式

#### 6.1.1 移动成功日志（单文件）

格式必须包含：

`Move: [{原文件名}] -> [{月目录名}]  :   From: ({原所在目录相对路径}) ,  {状态信息}`

说明：

- `{原所在目录相对路径}`：相对于根目录的父目录路径；根目录自身可记为 `.`
- `{状态信息}`：例如 `status=ok` 或 `renamed_to=xxx`

#### 6.1.2 跳过日志（同名同大小）

示例语义：

`Skip: [xxx] -> [YYYY_MM] : From: (...) , same_name_and_size(size=...)`

#### 6.1.3 失败日志

示例语义：

`Fail: [xxx] -> [YYYY_MM] : From: (...) , error=...`

#### 6.1.4 重名告警日志

发现重名并重命名时，需有单独告警日志，语义类似：

`[警告] 发现重名，自动重命名：old -> new`

### 6.2 开头日志（执行元信息）

每次执行开始时，日志顶部必须记录：

1. 本次实际执行命令行
2. 解析后的参数信息

### 6.3 末尾汇总日志

必须输出至少以下统计项：

- 成功数量（moved）
- 失败数量（failed）
- 跳过数量（skipped same file）
- 白名单过滤数量（filtered by whitelist）
- 重命名数量（renamed）
- 删除空目录数量（removed_empty_dirs）
- 总处理数量（total）

并输出按月份统计：

- `{月份目录} : 移入文件数`

---

## 7. 日志落盘需求

### 7.1 根目录总日志

每次运行结束后，必须在**原根目录**生成本次完整日志文件（含最终统计）：

- 命名规则建议：`ym_organize_{yyyyMMdd_HHmmss}_ops{总处理数}.log`
- 编码建议：`UTF-8 with BOM`（兼容 Windows 记事本）

### 7.2 月目录子集日志

每个有文件移入的月份目录中，必须生成“仅含单文件移动记录”的子集日志：

- 不包含最终汇总统计
- 命名规则建议：`ym_moves_{yyyyMMdd_HHmmss}_ops{该月移入数}.log`

### 7.3 日志内容与界面一致性

- 控制台日志、GUI日志、落盘日志在语义上保持一致
- 如果启用结构化事件输出，仍要保证日志可还原主要操作过程

---

## 8. 结构化事件协议（CLI -> GUI）

当启用 `--json-events` 时，CLI 输出事件行，供 GUI 解析：

- 事件行前缀：`__EVENT_`_ 
- 内容：JSON 字典

事件类型至少包括：

- `log`：普通日志消息
- `start`：任务开始（总数、目标根目录等）
- `progress`：进度（processed/total）
- `file_moved`：单文件移动成功
- `duplicate_skipped`：同文件跳过
- `name_conflict`：重名重命名
- `error`：单项错误
- `empty_dir_removed`：空目录删除
- `done`：最终统计
- `fatal`：致命错误（主流程异常）

要求：

- 事件 JSON 应尽量编码安全（跨平台避免乱码）
- GUI 仅依赖事件流即可完成日志与进度展示

---

## 9. GUI 功能需求

### 9.1 界面组件

GUI 至少包含：

1. 根目录输入框
2. “浏览”按钮（目录选择）
3. 可滚动日志显示区
4. 进度条 + 进度文本（`已处理/总数`）
5. 复选项：
  - 整理完成后删除空目录
  - 仅显示警告/错误
6. 主按钮：“按月整理”

### 9.2 目录拖拽（可选增强）

- 若安装 `tkinterdnd2`，支持将目录拖入输入框
- 未安装时应自动回退，不影响主功能，并给出提示

### 9.3 交互流程

点击“按月整理”后：

1. 校验目录合法性
2. 弹窗二次确认（同 CLI 的安全语义）
3. 禁用执行按钮，重置进度
4. 启动子进程调用 CLI（建议带 `--yes --json-events`）
5. 实时消费输出并刷新日志/进度
6. 结束后恢复按钮状态并显示结果

### 9.4 日志过滤

当启用“仅显示警告/错误”：

- GUI 日志区只显示警告、错误、stderr、fatal 等高优先级信息
- 过滤不应影响进度更新与最终统计接收

### 9.5 编码兼容

- 子进程输出解码建议使用系统首选编码（避免 Windows 乱码）
- GUI 必须容忍异常编码字符（`errors=replace` 类似策略）

---

## 10. 启动脚本需求（Windows）

需要提供一键启动脚本（`.bat`）：

- 双击即可启动 GUI
- 先切换到脚本所在目录
- 优先尝试 `py -3`，否则回退 `python`

---

## 11. 错误处理与稳定性要求

- 任一文件处理异常不得导致全任务崩溃
- 失败必须记录具体错误并继续后续文件
- 文件被占用、权限不足、路径异常等场景需要可见错误日志
- 主流程发生未预期异常时：
  - 返回非零退出码
  - 若启用事件流，输出 `fatal` 事件

---

## 12. 非功能需求

- **性能**：判重采用“同名+大小”快速策略，避免高成本全量哈希
- **一致性**：CLI 与 GUI 的统计口径一致
- **可维护性**：核心逻辑与界面逻辑分离（CLI/GUI 两层）
- **可追溯性**：每次执行都能通过落盘日志回溯操作明细与统计

---

## 13. 验收标准（可测试清单）

1. 可通过 CLI 和 GUI 两种方式完成按月整理
2. 目标目录按 `{root}_YM/YYYY_MM` 正确生成
3. 白名单为空时整理全部文件；白名单非空时仅整理命中后缀文件
4. 同名同大小文件会被跳过，不产生重复副本
5. 同名不同大小文件会重命名后移动，不覆盖原文件
6. 任意单文件失败不会中断整体流程
7. 启用空目录清理时，只删除原根目录下空子目录
8. 日志包含：
  - 开头命令行与参数
  - 逐文件操作记录（Move/Skip/Fail）
  - 最终汇总统计
  - 各月份移入统计
9. 根目录总日志与月目录子集日志均正确生成，命名带时间和操作数
10. GUI 进度与最终统计与 CLI 结果一致
11. Windows 场景无明显乱码问题

---

## 14. 非目标（本期不要求）

- 文件内容级精确去重（如全文件哈希严格判同）
- 回滚机制（失败后自动恢复全部原始状态）
- 多任务并发执行与任务队列管理
- 网络目录/远端存储特化优化

---

## 15. 术语说明

- 根目录：用户指定的待整理目录
- 目标备份目录：根目录同级、命名为 `{root}_YM` 的目录
- 月目录：目标备份目录下的 `YYYY_MM` 子目录
- 同文件（本工具定义）：同名且文件大小相同
